## 防止再次遗漏

```sh
npm run audit:upstream -- ../dnsmgr
npm run typecheck
npm test
```

`audit:upstream` 只读取 PHP 字面元数据，不执行外部 PHP。它检查字段未被省略、控件类型及显示条件可识别、设置键已登记、路由声明与审核基线一致。未知控件在 API 中显式返回 `UPSTREAM_ADAPTER_MISMATCH`，不再返回缺字段的“成功”表单。

GitHub 构建会检出 `HanadaLee/dnsmgr` 的 `ext` 并执行此检查；检查失败会阻止后续镜像构建。路由基线是人工审核记录，不应在未检查新功能时机械更新。

前端另有 `npm run test:browser`：使用本地测试页面验证真实浏览器中的必填、多域名粘贴、创建/编辑提交、条件切换及禁用。首次执行前运行 `npx playwright install chromium`；本机已有 Chrome 时可设置 `PW_BROWSER_CHANNEL=chrome`。测试页面不作为生产构建入口发布。

## 网关要求与验收边界

网关必须将 `/mcp` 和 `/qqbot/webhook` 精确转发到 helper，不能落入前端 SPA。保持原始请求体、Authorization 及 QQ 签名头，不对这些接口施加浏览器 SSO 跳转；原站负责各自的 API 密钥与回调签名验证。

本次检查包含源代码对照、本地自动化测试和浏览器表单测试。未调用真实云厂商接口、未执行真实证书部署、未发送 QQ 通知或改动线上数据。在线更新按既有要求继续移除；原站安装页面与原生登录流程由部署及 SSO 方案替代，不作为新前端页面补回。
